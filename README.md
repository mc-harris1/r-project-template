# R Project Template

A small, opinionated starting point for R projects that process data in
repeatable stages. The template keeps project orchestration, shared helpers,
and directory conventions separate from domain-specific work, and it works
identically whether you develop in VS Code or RStudio.

## Structure

```text
.
├── setup.R          # One-time, idempotent project bootstrap script
├── main.R
├── R/
│   ├── stage_0_load.R
│   ├── stage_1_process.R
│   ├── stage_2_analyze.R
│   └── utils_shared.R
├── data/
│   ├── raw/          # User-provided or downloaded inputs
│   ├── processed/    # Intermediate data products
│   └── features/     # Derived features ready for analysis
├── tests/
│   └── testthat/     # Unit tests and shared test setup
├── scripts/          # Lint and formatting commands
├── outputs/
│   └── plots/        # Generated figures and reports
├── renv.lock         # Resolved, reproducible package environment (created by setup.R)
└── renv/             # renv infrastructure (created by setup.R)
```

The data and output directories are ignored by Git. Their `.gitkeep` files
only preserve the initial project layout; replace them with real files as the
project develops. The `.Rproj` file and `renv/`/`renv.lock` are generated by
`setup.R` the first time you bootstrap the project, so they aren't committed
to the template itself.

## Getting started

This template uses [`usethis`](https://usethis.r-lib.org/) and
[`renv`](https://rstudio.github.io/renv/) — both editor-agnostic, standard R
tooling — instead of any IDE-specific configuration. Run the bootstrap script
once after cloning or creating a project from this template:

```sh
Rscript setup.R
```

Or, from an interactive R console (VS Code's R terminal or the RStudio
console):

```r
source("setup.R")
```

The script is safe to re-run. It will:

1. Install `usethis` and `renv` if they aren't already available.
2. Create (or confirm) the project's `.Rproj` file, which both VS Code's R
   extension and RStudio use to detect the project root and working
   directory.
3. Create the standard `R/`, `data/raw/`, `data/processed/`, `data/features/`,
   `outputs/plots/`, and `tests/testthat/` directories.
4. Add data-science-friendly rules to `.gitignore` (`data/raw/`, `.Rhistory`,
   `.RData`, `.env`, local editor settings, etc.).
5. Initialize `renv` (`renv::init()`), scanning the project for package usage
   and writing a `renv.lock` file for reproducible dependency isolation.

Restore a previously locked environment on later checkouts with:

```r
renv::restore()
```

Put source files in `data/raw/` or replace the loader stage with the
appropriate download or import code. Run the complete pipeline from the
repository root:

```sh
Rscript main.R
```

Add project-specific dependencies as you use them in code, then run
`renv::snapshot()` to update `renv.lock`, and commit the result.

### VS Code

1. Open the project folder (`code .`). Install the
   [R extension](https://marketplace.visualstudio.com/items?itemName=REditorSupport.r)
   and make sure an R installation is available on your `PATH`.
2. Open the integrated terminal — it starts at the project root, so no
   manual path resolution is needed.
3. Run `Rscript setup.R` in the terminal (or open an R interactive terminal
   and run `source("setup.R")`).
4. Restart the R terminal/session afterward so the `renv`-managed
   `.Rprofile` activates the project library automatically.

### RStudio

1. If the project doesn't yet have an `.Rproj` file, open the folder via
   **File > Open Project… > New Project > Existing Directory**, then run
   `source("setup.R")` once in the console. This creates the `.Rproj` file
   alongside everything else.
2. From then on, open the project by double-clicking the generated `.Rproj`
   file — RStudio sets the working directory and activates the `renv`
   library automatically.
3. Re-run `source("setup.R")` any time; it only changes what's missing.

## Pipeline stages

`main.R` sources the stages in order. Stage 0 must set `stage0_updated` to
`TRUE` when it creates or receives new input. The default skeleton sets it to
`TRUE` so the full example run is visible.

| Stage | Script | Responsibility |
| --- | --- | --- |
| 0 | `R/stage_0_load.R` | Load or acquire raw input and record whether it changed. |
| 1 | `R/stage_1_process.R` | Clean, transform, and save intermediate data. |
| 2 | `R/stage_2_analyze.R` | Create features, analyses, plots, or reports. |

Replace the placeholder behavior in each stage while keeping paths relative
to the project root. Add project-specific helpers to `R/utils_shared.R` only
when they are shared by multiple stages.

## Configuration

`renv::init()` (run via `setup.R`) creates `.Rprofile` and activates the
project-local package library automatically whenever R starts in this
project — in VS Code, RStudio, or a plain terminal. `.lintr` contains a
lightweight linting configuration. No editor-specific settings are committed
to the repository; `.vscode/` is gitignored so local, per-user editor
settings never leak into the shared project.

## Testing

Run the unit suite from the repository root:

```sh
Rscript tests/testthat.R
```

Tests use `tests/testthat/helper-load.R` to source the template's pipeline
scripts. Add project tests as `test-*.R` files in `tests/testthat/`.

## Code quality

Lint the R source:

```sh
Rscript scripts/lint.R
```

Format project-owned R source and tests before committing:

```sh
Rscript scripts/style.R
```

Install the repository hooks after installing the `pre-commit` CLI:

```sh
pre-commit install
```

`.pre-commit-config.yaml` applies tidyverse R styling, checks R syntax, blocks
`browser()` and `print()` statements, and enforces standard whitespace and
large-file checks. Generated `data/` and `outputs/` files are excluded from
the R-specific hooks.

GitHub Actions runs linting and tests on every push and pull request against
`main`, installing R and dependencies with the standard `r-lib/actions`
toolchain.

This template intentionally contains no data source, statistical method, or
domain-specific analysis. A financial-market workflow such as
`tda-financial-markets` can serve as an example of how to specialize these
stages, but its data, dependencies, and analysis code do not belong here.
